# 日記の提出向け編集案（未公開）

2026-10-11に公開本文とコードを確認した編集差分です。本番CMSは更新していません。記事のURL・公開日・カテゴリー・画像・外部リンク・既存の関連記事／関連ページは維持します。実績詳細の前回修正も維持します。

## 編集する場所

| 対象 | 管理経路 | 今回の差分 |
| --- | --- | --- |
| 記事H1・一覧カードのタイトル | microCMSの対象サービス → `blog` API → コンテンツID → `title` | 既存値をソースで上書きしない。変更する場合はCMS側の下書きで行う |
| 記事の導入文 | 同じコンテンツの `description` | 今回は変更不要 |
| 記事本文・本文画像 | 同じコンテンツの `content` | 下記の段落移動・見出し追加・短い置換案。ソースには本文を埋め込まない |
| 検索結果・OGPタイトル | CMSの任意 `seoTitle`、空欄なら `lib/contentSeo.ts` の既存フォールバック | `site-renewal` のフォールバック1件だけを訂正。CMSの `seoTitle` は引き続き優先 |
| 日記一覧のおすすめ枠 | `app/diary/page.tsx` / `page.module.css` | 指定した3IDの公開タイトル・説明をCMSから取得する |

経路のコード根拠は `app/_libs/microcms.ts` の `getBlogDetail`（endpoint `blog`）、`app/_components/Article/index.tsx` の `data.title` / `data.description` / `data.content`、`lib/contentSeo.ts` のCMS優先処理です。サービス名や管理画面URLは認証情報から取得していません。

CMS編集前に現行コンテンツを保存し、公開ボタンは押さず下書きで確認します。`publishedAt`、コンテンツID、category、description、thumbnailは今回の編集で変更しません。本文の移動はリッチエディタ上の段落／画像ブロック単位で行い、画像とキャプション・リンクを落とさないでください。`seoTitle` が既に入力済みなら、コードの変更だけではその値は変わりません。

日記一覧の通常表示にだけ「開発・学習のおすすめ記事」を追加しました。順番は `iropon-release` → `commu-type-check` → `site-renewal`。現在のCMSタイトル・説明を表示し、本文変更の準備段階でも別タイトルや技術実績を作りません。記事本文は取得しません。
